// 02

Do chat ao agente

O problema

Sem tools, o modelo só vê o que você cola. E você vira o copia e cola dele.

A virada

Com tool calling ele lê e escreve arquivos, busca no código, roda comandos e checa erros. Várias tools em sequência formam um agente.

Quem dirige é você. O agente executa. Entender, planejar, testar e revisar continua sendo seu trabalho.

  1. 1. Explore o código
  2. 2. Planeje no Plan Mode
  3. 3. Revise o plano e clique em Build
  4. 4. Teste e revise
  5. 5. Vire o aprendizado numa Rule

Na prática: pasta vazia, chat novo. Antes da primeira mensagem o anel já mostra system prompt, tools, rules, skills e MCP. Um prompt curto pede a landing (hero, recursos, chamada para importar o extrato). Depois da resposta o anel sobe, porque tudo virou contexto.

// 03

O que é um token

A unidade de texto do modelo. A moeda da IA. É o que você paga.

3/4

de uma palavra em inglês, por token, como referência

128 mil

tokens cabem de uma vez, cerca de 96 mil palavras

300

páginas, o livro que essa janela equivale

Tipos de tokens

Input

Tudo o que você envia: system prompt, prompt do usuário, contexto.

Output

Tudo o que o modelo gera: texto, código, tool calls. Costuma custar 2 a 4 vezes o input.

Cache read

Cerca de 10 vezes mais barato, a cada turno da mesma conversa. No Opus, $0,50 contra $5 do input, por 1M.

Cache write

Caro. Acontece no início da conversa ou quando entra conteúdo novo. Escreve o cache.

Mantenha o começo estável: Rules entram no início do contexto. Cada tool call reenvia o contexto e aparece como cache read.

Qual modelo para a tarefa

Modelo maior não é sempre melhor. Pergunta simples em modelo caro é desperdício.

Raciocínio

Claude 4.7 Opus

Input $5 por 1M. Output $25 por 1M.

Rápido

Composer 2.5

Input $0,50 por 1M. Output $2,50 por 1M. 10 vezes menos por token.

Modelos rápidos para edições simples. Modelos mais capazes para raciocínio e refactors grandes. Dá para trocar no meio da conversa.

// 04

Uma conversa que só cresce

Você pede uma feature. O agente lê arquivos, roda testes, você pede um ajuste. Cada turno reenvia tudo, e a conversa só cresce. Cada chamada reenvia o histórico e você paga de novo.

Contexto pequeno e certo: só o que a tarefa precisa, e chat novo quando a tarefa muda.

O que é contexto

Não é a memória inteira do modelo. É como a RAM: tem limite e é limpa a cada sessão.

Tudo o que a IA faz entra aqui, não só o seu prompt.

  • System prompt
  • Prompt do usuário
  • Resposta
  • Lista de tools
  • Chamada de tools
  • Rules

O anel de contexto

128 mil tokens é o que cabe de uma vez. Quando enche, o Cursor resume a conversa e detalhes se perdem. Olhe o anel ao lado do prompt. Clique nele para ver o que ocupa espaço: system prompt, tools, rules, skills, MCP e a conversa.

Referencie, não cole

Antes: colar

O código vira texto solto, sem o caminho do arquivo, e entra inteiro no contexto.

Depois: @

O agente sabe onde o arquivo está e pode ler só o trecho que importa.

@src/components/ para uma pasta. @Terminals para a saída do terminal. @Chats para trazer outra conversa. Use @ quando souber quais arquivos importam. Peça a resposta, não o arquivo: "@auth.ts, onde o token expira?" Sem @ quando não souber por onde começar: o agente busca sozinho.

Referencie. Nunca copie e cole.

Na prática: escreva o briefing da landing num arquivo e peça a atualização com @ nos dois caminhos. Noutro chat, cole o briefing inteiro e compare o anel. Se o servidor falhar, pergunte com @Terminals.

Rules com menos de 500 linhas

Critério repetido em todo prompt vira input novo toda vez. Escreva numa Rule em .cursor/rules, com escopo por globs ou por descrição. Menos de 500 linhas. Rules entram no início do contexto.

No app de finanças, a rule de categorias (mercado, transporte, moradia, lazer) aponta para os arquivos de categorias. Ela aparece no anel, na categoria Rules.

O arquivo que o agente não viu

.gitignore

Oculta da indexação. node_modules/, logs/. O agente ainda pode ler o .env.

.cursorignore

Bloqueia o acesso do Agent, do Tab e do @. .env, package-lock.json, logs, builds.

O que não entra não custa token e não vaza.

O manual na prateleira

Instruções longas numa Rule sempre ativa ocupam contexto em todo turno. Numa Skill, só nome e descrição ficam fixos. O conteúdo entra quando a tarefa pede. O agente vê a lombada e só abre o manual na hora.

A skill de importar extrato CSV fica assim até você invocá-la pelo menu / com um extrato de exemplo. O corpo entra nesse momento, não antes.

Toda tool tem preço

A definição entra no input, com algumas centenas de tokens por tool, e o resultado entra no contexto. Prompt preciso, menos exploração: diga o arquivo e o objetivo para o agente chamar menos tools.

Carregar só os MCPs necessários reduziu 46,9% dos tokens nas execuções com MCP.

O ganho varia com quantos servidores você instalou. Ative só os que a tarefa usa e desligue o resto. Saídas longas e o terminal podem virar arquivos que o agente lê por partes. Depois de um resumo, ele consulta o histórico em vez de guardar tudo na janela.

Mande um batedor

Uma varredura grande no chat principal deixa cada arquivo lido no histórico. Delegue a exploração a um subagent e traga só o resumo. O batedor volta com o mapa.

O resumo automático é uma compressão com perdas. Antes do próximo chat: peça uma nota de handoff curta, abra um chat novo, use @ na nota, e @Chats só se faltar algo.

Na prática: a nota diz que a landing está pronta, com a rule de categorias e a skill de extrato. O chat novo lê a nota e cria um backend SQLite para as transações importadas. Um subagent pode mapear a landing e devolver só os campos que a API precisa. Se der erro, @Terminals. Compare o anel e o Usage desse chat com o chat longo da landing.

// DIRETRIZ DE EXECUÇÃO

CONFIRMAR ANTES

“Uma ferramenta cara escreve uma enciclopédia no chat. Pergunte primeiro. Se a resposta for não, nada entra.”

Modelos soltos chamam ferramentas de varredura que cospem três mil linhas de dump, árvore recursiva de diretórios e cabeçalhos inúteis. Essa poeira sufoca o raciocínio. O protocolo de tranca impõe um diálogo breve de consentimento: a ação é resumida, o custo é previsto e a resposta negativa aborta o consumo antes do estrago.

Sem confirmação Desperdício

A ferramenta é acionada às cegas. Um payload cru de terminal e metadados enche a memória. O modelo perde o foco central tentando ignorar o lixo despejado.

$ scan_full_repo --all
> 4.892 arquivos mapeados (32.000 tokens injetados)
Com tranca ativa Cirúrgico

Uma linha interroga o operador: "Deseja inspecionar o arquivo X?". Ao recusar ou restringir, zero tokens indesejados entram na conversa.

[TRANCA] Executar leitura profunda? [S/N]
> N // Sala limpa preservada
// SUPERFÍCIES PERIGOSAS

BLOQUEAR O QUE É ARRISCADO

Duas saídas que precisam de ferrolho duplo permanente.

Porta 01 Isolado

Subshell Local

Tranca total para comandos imprevisíveis de terminal ou compilações que vagam sem rumo. O agente formula a modificação como diff de texto e jamais roda o comando sem barreira estrita.

Porta 02 Isolado

API Opaca e Externa

Tranca baixada para conexões de rede sem filtro estrito. Nenhuma API externa jorra dados crus no contexto. As respostas precisam ser resumidas fora da sala e entregues como recibo enxuto.
