From chat to agent

The problem

Without tools, the model only sees what you paste. You become its copy and paste.

The turn

With tool calling it reads and writes files, searches the code, runs commands, and checks errors. Several tools in a row make an agent.

You still drive. The agent executes. Understanding, planning, testing, and review stay your work.

  1. 1. Explore the code
  2. 2. Plan in Plan Mode
  3. 3. Review the plan and click Build
  4. 4. Test and review
  5. 5. Turn the lesson into a rule

Try it: an empty folder and a new chat. Before the first message the ring already shows the system prompt, tools, rules, skills, and MCP. A short prompt asks for the landing page (hero, features, a call to import the statement). After the reply the ring climbs, because all of that became context.

What a token is

The model's unit of text. The currency of the AI. It is what you pay.

3/4

of an English word, per token, as a rough measure

128k

tokens fit at once, about 96,000 words

300

pages, the book that window is roughly worth

Kinds of tokens

Input

Everything you send: system prompt, user prompt, context.

Output

Everything the model generates: text, code, tool calls. Output often costs 2 to 4 times the input.

Cache read

About 10 times cheaper, on every turn of the same chat. On Opus, $0.50 against $5 of input, per 1M.

Cache write

Expensive. It happens at the start of a chat, or when new content arrives. It writes the cache.

Keep the start of the chat stable: rules sit at the front of the context. Each tool call resends the context and shows up as a cache read.

Which model for the task

A larger model is not always better. A simple question on an expensive model is waste.

Reasoning

Fast

Composer 2.5

Input $0.50 per 1M. Output $2.50 per 1M. 10 times less per token.

Fast models for simple edits. More capable models for reasoning and large refactors. You can switch in the middle of a chat.

// 04

A chat that only grows

You ask for a feature. The agent reads files, runs tests, you ask for a tweak. Every turn resends everything, and the chat only grows. Every call resends the history, and you pay for it again.

Small, right context: only what the task needs, and a new chat when the task changes.

What context is

It is not the model's whole memory. It is like RAM: it has a limit, and it is cleared each session.

Everything the AI does lands here, not only your prompt.

The context ring

128 thousand tokens is what fits at once. When it fills, Cursor summarizes the chat and details drop out. Look at the ring beside the prompt. Click it to see what takes space: system prompt, tools, rules, skills, MCP, and the conversation.

Reference, do not paste

Before: paste

The code becomes loose text, with no file path, and the whole thing enters the context.

After: @

The agent knows where the file is and can read only the span that matters.

@src/components/ for a folder. @Terminals for the terminal output. @Chats to bring in another conversation. Use @ when you know which files matter. Ask for the answer, not the file: "@auth.ts, where does the token expire?" Skip @ when you do not know where to start: the agent searches on its own.

Reference. Never copy and paste.

Try it: write the landing brief in a file and ask for the update with @ on both paths. In another chat, paste the whole brief and compare the ring. If the dev server fails, ask with @Terminals.

Rules under 500 lines

A criterion you repeat in every prompt becomes fresh input every time. Write it as a rule in .cursor/rules, scoped by globs or by description. Under 500 lines. Rules sit at the start of the context.

On the finance app, the category rule (groceries, transport, housing, leisure) points at the category files. It shows up on the ring, under Rules.

The file the agent never saw

.gitignore

Hides files from indexing. node_modules/, logs/. The agent can still read .env.

.cursorignore

Blocks Agent, Tab, and @. .env, package-lock.json, logs, builds.

What does not enter does not cost a token, and it does not leak.

The manual on the shelf

Long instructions in an always-on rule take context on every turn. In a skill, only the name and the description stay fixed. The body enters when the task asks. The agent sees the spine and opens the manual then.

The bank-statement CSV skill stays that way until you invoke it from the / menu with a sample statement. The body enters at that moment, not before.

Every tool has a price

The definition enters the input, a few hundred tokens per tool, and the result enters the context. A precise prompt means less wandering: name the file and the goal so the agent calls fewer tools.

Loading only the MCPs a task needs cut 46.9% of the tokens on runs that used MCP.

The gain varies with how many servers you have installed. Turn on only the ones this task uses and switch the rest off. Long outputs and the terminal can become files the agent reads in parts. After a summary, it looks back at the history instead of keeping everything in the window.

Send a scout

A wide search in the main chat leaves every file it read in the history. Delegate the exploration to a subagent and bring back only the summary. The scout returns with the map.

An automatic summary is a lossy compression. Before the next chat: ask for a short handoff note, open a new chat, use @ on the note, and @Chats only if something is still missing.

Try it: the note says the landing page is ready, with the category rule and the statement skill. The new chat reads the note and creates a SQLite backend for imported transactions. A subagent can map the landing page and return only the fields the API needs. If it errors, use @Terminals. Compare that chat's ring and Usage with the long landing chat.

// THE CONTAINMENT DRILL

Three mechanical moments at the threshold.
Step 01

Door shut, hallway empty

No call fires without permission. The context window sleeps without side noise.

Step 02

Hand on the lock, still shut

An expensive tool asked to run. The trigger freezes: the operator must authorize it before a single token is spent.

Step 03

A crack open: the slip passes

Only four lines of a surgical finding cross the threshold. The log boxes stay in the hallway.

// EXECUTION RULE

CONFIRM FIRST

“An expensive tool writes an encyclopedia into the chat. Ask first. If the answer is no, nothing enters.”

Loose models call scan tools that dump three thousand lines, a recursive directory tree, and useless headers. That dust smothers the reasoning. The lock protocol forces a short consent exchange: the action is summarized, the cost is forecast, and a no aborts the spend before the damage.

Without confirmation Waste

The tool fires blind. A raw terminal payload and its metadata fill the memory. The model loses the central thread trying to ignore the dumped junk.

$ scan_full_repo --all
> 4,892 files mapped (32,000 tokens injected)
With the lock on Surgical

One line asks the operator: "Inspect file X?". A refusal or a narrower scope lets zero unwanted tokens into the conversation.

[LOCK] Run a deep read? [Y/N]
> N // Clean room kept
// DANGEROUS SURFACES

BLOCK WHAT IS RISKY

Two exits that need a permanent double bolt.

Door 01 Isolated

Local subshell

A full lock on unpredictable terminal commands or compiles that wander. The agent writes the change as a text diff and never runs the command without a strict barrier.

Door 02 Isolated

Opaque external API

The lock stays down for unfiltered network calls. No external API pours raw data into the context. Answers are summarized outside the room and delivered as a short receipt.

// PEAK CONCENTRATION

QUIET ROOM

When nothing enters without a need, the model's intelligence stays clean.

Tool tray Empty

Without dozens of function schemas taking slices of attention. The working space stays fully available for the problem.
